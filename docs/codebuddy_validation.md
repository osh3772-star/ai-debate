# CodeBuddy DeepSeek Flash 추가 검증

날짜: 2026-10-19 (한국 시간). 사용자의 최신 지시인 **토론 테스트 금지**를 적용했다.

## 설치·인증·모델

- 기존 공식 npm 패키지 `@tencent-ai/codebuddy-code` 2.169.0을 재사용했다. 재설치하지 않았다.
- CLI `--help`, 설치 패키지 제품 모델 목록에서 `deepseek-v4.1-flash`를 먼저 확인했다.
- 원래 로그인 저장소를 CLI가 직접 재사용했다. 자격증명 파일의 내용을 읽거나 복사하지 않았다.
- 공식 `codebuddy` npm 명령이 실행하는 동일 Node 진입점을 직접 호출한다. Windows npm `.cmd`를 경유할 때 빈 `--tools` 인자가 사라지는 것을 피하기 위한 것이다. 게이트웨이·API SDK는 사용하지 않는다.
- 실제 실행 옵션: `-p --output-format json --model deepseek-v4.1-flash`, 도구 빈 목록, MCP 빈 목록/strict, 설정 소스 none, 훅 비활성화, 세션 저장 안 함, 새 세션 ID, 단일 내부 턴.
- 자식 프로세스에서 API·게이트웨이·제품 설정 override 환경을 제거하고 `CODEBUDDY_DISABLE_CUSTOM_MODELS_FILE=1`, `CODEBUDDY_CODE_DISABLE_BACKGROUND_TASKS=1` 적용. 이후 API 키·API helper 비활성화 옵션도 추가했다. 전역 설정·로그인은 수정하지 않았다.
- `wb-openai-gateway` 설치·실행·호출 없음.

## 실제 단독 연결

사용자 과제 자료 없이 무작위 확인 문자열만 전달했다. 토론은 하지 않았다.

1. 첫 단독 호출은 JSON 응답을 받았으나, CodeBuddy의 원본 이력 형식을 모델 검증기가 인식하지 못해 실패로 기록했다. 성공으로 집계하지 않는다. 기록: `runs/individual-tests/codebuddy-997f0b1d.json`.
2. 공식 패키지 출력 형식에 맞춰 파서를 수정한 후 단독 연결을 한 번 더 확인했다. 기대한 문자열과 실제 응답이 일치하고, 응답 이력의 `providerData.model`이 **deepseek-v4.1-flash**로 확인됐다. 모델 자기소개나 요청 인자만으로 확인하지 않았다. 기록: `runs/individual-tests/codebuddy-1080658d.json`.

성공 응답 사용량: 입력 6,307, 출력 14 토큰. 캐시 생성 입력 3,363, 캐시 읽기 입력 2,944. CLI가 제공한 사용량 기록이며 별도 합산 청구량으로 해석하지 않는다.

모델 증거는 공식 CLI가 기록한 응답 모델 메타데이터다. 설치 소스에서 이 필드가 서비스 응답의 모델을 우선 기록하고, 응답에서 모델을 생략하면 선택 모델로 대체할 수 있음을 확인했다. 서버 내부 실행을 별도로 증명하는 기록은 아니다.

**비용 주의:** 해당 CLI 버전은 JSON의 `total_cost_usd`를 0으로 고정한다. 따라서 이 값은 무과금의 증거가 아니다. 별도 API 키·API fallback·결제 경로는 없고 기존 CodeBuddy 계정의 한도/크레딧 정책이 적용된다. 실제 청구 내역·잔여 한도는 확인하지 않았다.

## 시스템 변경

- 기존 GPT·Claude·Gemini 설정과 자료 선택 12개를 그대로 유지하고 네 번째 DeepSeek 참가자를 추가했다.
- 원래 설정은 `ui_config.before-codebuddy.json`에 보존했다.
- 저장 UI 모드를 4단계 합의 토론으로 선택했다. 기존 PBL·2라운드 모드는 유지했다.
- 독립 분석 → 교차 반박 → 재반론 → 최종 합의 검토, 4명 기준 16개 슬롯. 최종 동의·이견·소수의견을 보존하며 전원 합의를 자동 판정하지 않는다.
- 새 발언마다 독립 임시 CLI 세션을 만들고 문맥은 엔진의 JSON 기록으로 전달한다. 중단·재개 때 완료된 슬롯은 건너뛴다.
- 인증/한도/모델 불일치/타임아웃 오류를 분류하고 해당 시도를 실패로 저장한다. 자동 재시도·모델 교체는 없다.
- JSON/원본 토론/분류별 요약 화면에 네 번째 참가자와 재반론·최종 의견을 연동했다.
- 실행 중 토론 0개를 확인하고 해당 프로젝트의 UI 서버만 재시작했다. 새 서버는 127.0.0.1:8765에 바인딩한다. 시작·재개는 호출하지 않았다.

## 검증 범위

- Python 테스트: 최종 전체 재검 **46개 통과**. 그중 CodeBuddy 관련 20개는 모든 실제 프로세스 실행을 차단한 오프라인 검사다. 네이티브 JSON 배열을 UI 스트림 이벤트로 오인하지 않는 회귀 검사도 포함한다.
- 분류 웹 테스트: **21개 통과**, HTTP·AI 호출 없음.
- 제어기 조회·설정 보존 계약 검사: 통과.
- 최종 재검 중 Windows 임시 HTTP 연결 리셋(10053)이 한 번 발생했다. 해당 인증/CSRF 차단 검사를 단독 재실행해 통과했고 실제 모델 호출은 없었다.
- 브라우저: 4명, DeepSeek V4.1 Flash, 4단계 합의 모드, 자료 12개, 전송 동의 미체크, 저장된 최근 연결 성공 확인.
- 원래 두 연구 실행의 JSON·발언 수를 보존했다. 새 토론 실행 폴더를 만들지 않았다.
- 실제 4인 토론·16회 발언·최종 합의 품질은 검증하지 않았다. 사용자가 토론 테스트를 금지했기 때문이다.
