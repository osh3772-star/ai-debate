# 선택적 공개 웹 검증

2026-10-20 적용. 공식 CLI 로그인과 기존 모델 선택을 사용하며 별도 유료 API·프록시를 추가하지 않습니다.

## 사용 방법

새 연구 설정의 **필요 시 공개 웹 검색·원문 검증**을 켠 뒤 사용자가 연구 시작을 누릅니다. 새 연구의 기본값은 켜기입니다. 자료가 충분하면 검색하지 않도록 지시하며 근거 누락·충돌·최신성 문제, 외부 수치·인용 확인을 우선합니다. 연결 테스트 모드는 검색을 끕니다.

기존 저장 실행을 재개할 때는 당시 정책을 유지합니다. `web_research`가 없는 예전 실행은 꺼진 상태입니다. 새 체크박스가 예전 발언·실행 정책을 소급 변경하지 않습니다. 새 연구를 시작하면 선택한 정책이 적용됩니다.

터미널 새 연구는 기본 허용이며 `--no-web-research`로 끌 수 있습니다. 실제 모델 호출은 기존 전송 동의 및 실행 명령이 있어야 합니다.

## 공급자별 허용 범위

|공급자|검색 켜기|유지되는 제한|
|---|---|---|
|Codex|`web_search="live"`|읽기 전용, shell 도구 끄기, ChatGPT 로그인|
|Claude Code|`WebSearch,WebFetch`만 도구 목록에 노출·허용|파일·명령·MCP 차단, hooks 끄기, Claude 구독 로그인|
|Google Antigravity|호출 중 `read_url(*)` 허용|파일·명령·웹 조작·MCP 차단, G1 크레딧 사용 끄기, 호출 뒤 원 설정 복원|
|CodeBuddy|`WebSearch,WebFetch`만 노출·허용|MCP·hooks 끄기, 기존 DeepSeek 모델 고정·응답 모델 확인, API 키 경로 차단|

Claude와 CodeBuddy는 검색을 포함한 내부 처리에 최대 10턴을 허용합니다. 전체 발언 시간 제한·중단 처리는 유지합니다. 검색에는 구독 사용량과 시간이 더 들 수 있습니다. 도구의 모델·계정별 지원 여부와 실제 사용량은 공급자에 따릅니다.

공개 HTTP(S) 자료만 사용하고 과제 전문·개인정보·인증정보·비공개 사례 고유명과 수치를 검색어나 URL에 넣지 않도록 지시합니다. 공개 검색어만 사용한다는 규칙은 모델 지시이며 별도 네트워크 검사 프록시로 강제하는 기능은 아닙니다.

## 근거 기록

모델 응답의 `web_checks`에 주장 ID, 검색 필요 이유·검색어, 실제 열람/시도 URL·제목, 확인 시점, 근거 문단, 지지/충돌/판단 불충분/접근 실패와 한계를 기록하도록 요청합니다.

- 요약 화면 → 근거·검증 영역 → **공개 웹 검증 기록**
- `evidence_register.md` → 선택적 웹 검증 기록
- `debate.json` → 각 발언 `parsed.web_checks` 및 공급자가 반환한 `raw` 도구 이벤트

검색 결과 요약만으로 원문 확인을 주장하지 않습니다. 기록은 모델 자기 보고이며 시스템의 독립적인 사실 확인으로 승격하지 않습니다. 기록이 없거나 도구가 실패하면 미확인입니다. 원본 발언과 도구 이벤트를 대조할 수 있게 보존합니다.

## 검증 범위

공식 문서와 설치된 CLI 도움말로 옵션을 확인했습니다. 오프라인 테스트에서 도구 허용 범위, Google 설정 복원, 엔진의 정책 전달, 기존 실행 호환성, 잘못된 응답 처리, 출처대장 및 웹 화면 표시를 확인합니다. 이번 수정 작업에서는 실제 모델 호출·연구 토론을 실행하지 않았으므로 공급자별 실제 검색 성공을 입증한 것은 아닙니다.
