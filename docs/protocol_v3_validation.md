# 연구 프로토콜 v3 적용·검증 기록

적용일: 2026-10-21. [설계 검토](debate_protocol_design.md)의 후속 구현 기록이다.

## 적용한 동작

- 새 연구는 독립 조사 → 교차 검증 → 반론 응답 → 후보 비교 → 관점·실패 검토 → 교수 비판 → 수정·최종 판단의 7절차로 실행한다. 4명이면 기본 28회 호출이다. 합의·검증 모드는 기존 6절차를 유지하면서 단계별 출력 계약을 적용한다.
- 공통 프롬프트에서 조기 C 선정·최종 판단 임무를 제거했다. C 씨앗은 미평가 배열에 보존하고, 교차 검증·반론 응답의 공유 입력에서 이 구조화 배열과 초기 제안 배열을 제외한다.
- 같은 단계의 공통 입력을 이전 단계까지만 고정하고 ID·자료·응답 해시를 저장한다. 재개 시 공통 입력이 바뀌면 모델 호출 전에 중단한다.
- 주장·반박·후보에 발언별 ID를 부여하고, 교차 검토 누락·인용 불일치·잘못된 참조·핵심 반박 미해결을 추적한다. 과제 사실의 파일·행 존재도 검사한다.
- 호출 완료와 검토 상태를 분리했다. 최종 단계 전의 확정 판단은 권고로 집계하지 않고, 필수 근거·응답·참조가 부족하면 최종 권고를 보류한다. 모델의 원래 판단 문구는 원답변에 보존한다.
- 회계윤리 PBL/일반 분야를 사용자가 명시한다. 일반 주제에는 회계 이론과 절충 C를 강제하지 않는다. 1~2회 자유 토론을 전체 연구·합의 완료로 표시하지 않는다.
- UI에 미평가 후보, 후보별 비용·가정·실행·윤리·일정 위험, 원주장→반박→응답, 검토 대기·권고 보류를 표시한다.
- 기존 Markdown·JSON 파일명을 유지하며 구조화 검토 기록을 추가한다. 일반 분야의 보고서 목차에는 회계 사례의 기업가치·상장 일정을 넣지 않는다.
- 모델 응답·공급자 원시 이벤트·진단을 저장하기 전에 비밀정보·이메일 등 기존 마스킹 규칙을 적용한다. 인증 파일이나 전역 CLI 설정은 변경하지 않는다.
- 기존 실행의 단계 순서는 유지한다. 새 절차는 `protocol_version=3`인 새 실행에 적용한다. 구버전 서버에 새 UI만 연결된 경우 새 연구 시작을 차단하고 서버 재시작을 안내한다.

## 변경 파일

- `research_protocol.py`: 단계 정의·출력 계약·공유 입력·ID·참조/응답/권고 상태 검사.
- `debate.py`: 새 프로토콜 연결·입력 용량 검사·저장 전 마스킹·연구 자료 출력.
- `ui_server.py`: 새 실행의 분야·버전 저장, 검토 상태와 서버 기능 반환.
- `web/summary.js`, `web/controller.js`, `web/index.html`: 상태·추적·후보 UI, 분야 선택·호환 안내.
- `web/app.js`, `web/style.css`: 기존 `build_web.py`로 재생성한 실제 제공 파일.
- `test_protocol_v3.py`, `test_summary_contract.js`: 새 절차와 실제 제공 번들의 오프라인 검증.
- `UI_GUIDE.md`: 사용법 보완.

## 검증의 한계와 운영 상태

이번 작업에서 실제 AI 호출·토론·연결 테스트·추가 결제·커밋은 수행하지 않았다. 모델의 문장 품질과 실제 보고서 개선 효과는 검증하지 않았다.

자동 검사는 참조·인용·자료 행 존재·응답 연결을 검사한다. 회계 해석의 진위나 반박이 충분히 해결됐는지는 독립 원문 대조가 필요하다. 구조화 씨앗을 공유 입력에서 제외해도 모델이 지시를 어기고 분석 본문에 아이디어를 섞는 것까지 의미적으로 차단하지는 않는다. 그 가능성을 줄이도록 출력 지침을 분리했다.

현재 핵심 주장·반박·응답의 공유 입력 한도는 48KB다. 필수 기록이 초과하면 임의로 잘라 검토 완료로 처리하지 않고 호출 전에 중단한다. 범위가 큰 실행에서는 참가자 수나 쟁점 범위를 줄인 새 실행이 필요할 수 있다. 미확인 핵심 근거로 인해 권고가 보류되면 자료를 보완해 새 실행하거나, 기존에 제공되는 명시적 보완 호출을 사용자가 선택해야 한다. 자동 재질문 반복은 추가하지 않았다.

서버는 localhost에서 대기 중이다. 사용자가 **새 연구 시작**을 누르기 전 모델 호출은 없다. 기존 실행의 **재개**는 그 실행에 저장된 구버전 절차를 유지한다.
