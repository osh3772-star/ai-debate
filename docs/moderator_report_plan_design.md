# 총괄 최종 권고 → SECTION 1~5 작성안 설계

2026-10-23 · 기존 토론 기록 재사용 · 토론 재실행 없음

## 목적과 완료 기준

사용자가 모든 후보와 발언을 다시 읽고 결론부터 결정해야 하는 부담을 줄인다. 총괄은 동일한 평가 기준으로 권고 후보 하나를 선택하고, 그 선택을 뒷받침하는 SECTION 1~5 작성 재료를 구성한다. 전원 동의는 완료 조건이 아니다. 선택 이유, 기각 이유, 지금 할 일, 실행 조건, 실패 시 행동과 소수의견을 함께 남긴다.

보고서의 권고 방향과 실제 실행 가능성, 제출 준비 상태를 분리한다. 예를 들어 하나의 C안을 선택했더라도 현금 계획은 미확인일 수 있고, 선택 근거가 존재해도 제출용 출처 검증은 남아 있을 수 있다. 이런 경우 선택 자체를 없애거나 전체를 ‘보류’로 뭉뚱그리지 않는다.

완료 화면에는 후보 하나의 쉬운 이름과 권고 이유, 실행 행동, SECTION별 요점·연결 근거·가정·미확인 사항·부록 경로가 있어야 한다. 읽기만으로 모델을 호출하지 않는다. 완성 제출본을 자동 확정하지 않으며 학생이 자신의 문장으로 마무리할 수 있는 작성안이다.

## 두 가지 사용 경로

1. **기존 기록 보기:** 저장된 총괄 권고가 있으면 그대로 읽는다. 서버는 최종 판단·손익·실패 분석 등을 SECTION별로 분류한다. ‘기존 총괄 권고로 구성한 작성 자료’로 표시하며, 새 모델이 작성했다고 주장하지 않는다. 원래 권고가 없으면 투표수나 첫 후보로 임의 선택하지 않는다.
2. **총괄 권고·작성안 생성:** 사용자가 버튼을 누르고 저장 기록 전송을 확인하면 기존 공식 CLI로 총괄 1회만 호출한다. 동일 응답에서 최종 권고와 SECTION 1~5 작성안을 얻는다. 새 토론·새 검색·다른 참가자 재호출·자동 재시도 루프는 없다. 실패·한도·중단 시 기존 기록은 계속 읽을 수 있다.

현재 대화에서 수행하는 작업은 설계·구현과 오프라인/저장 기록 검증이다. 버튼을 대신 누르지 않는다.

## SECTION 배치

|제출 순서|분석 작업|핵심 작성 재료|
|---|---|---|
|SECTION 1 Executive Strategy Memo|STEP 4|최종 C안 → S 전제 → C 문제 → Q 질문 → 선택 이유·이사회 요청|
|SECTION 2 AI 환각 감사·합리화 진단|STEP 1|실제 원질문·오답·검토·개선 질문·개선 답변, 합리화·인지부조화|
|SECTION 3 장기 사회 효용 평가|STEP 2|이해관계자별 A/B/C 손익, 가정·산식·입력값, 세 윤리관의 연결|
|SECTION 4 회계 부정·대안 C 실행계획|STEP 3+4|네 회계 쟁점, 사기 삼각대, 독립성 통제, 일정·담당·자금·전환 절차|
|SECTION 5 Pre-Mortem·Kill Conditions|STEP 5|가장 강한 실패 사례, 관찰 지표·정량 기준·책임자·중단 후 행동|

SECTION 1은 약 1페이지, SECTION 2~5는 나머지 약 3페이지를 편집 목표로 한다. 웹 글자 수로 실제 A4 4페이지 준수를 확정하지 않는다. 상세 계산·기준서·감사·대화는 부록에 연결한다.

## 근거와 결정 규칙

- 과제 적합성, A·B 단점 감소, 실행 가능성, 핵심 반박 처리 여부로 후보를 비교한다. 임의 점수나 단순 다수결로 고르지 않는다.
- 새 작성안은 후보 ID 하나를 실제 후보 목록과 대조한다. 존재하지 않거나 여러 후보를 선택하면 검토 필요로 표시하고 프로그램이 첫 후보를 대신 고르지 않는다.
- 모델은 근거 ID를 제시하며, 표시할 근거 본문과 출처는 서버가 저장 기록에서 가져온다. 연결 존재 확인은 내용의 참·거짓 검증과 구분한다.
- 초기 ‘B 지지’ 잠정 계획을 최신 C안의 최종 계획처럼 복사하지 않는다. 후반 정정·반박 응답을 우선한다. 수정 전 주장은 감사 이력으로 남긴다.
- 숫자·출처·환각 사례·학생의 첫 생각을 만들어 채우지 않는다. 효용 산식과 Kill 기준에 실제 값이 없으면 가정과 필요한 입력을 구분한다. AI 교정 후보와 실제 교정 재호출도 구분한다.
- 총괄 입력에는 실제 반박 응답과 SECTION 3·5의 구조화 손익·실패 분석을 포함한다. 입력 한도와 생략 범위를 기록하고, 필수 자료가 한도를 넘으면 모델 호출 전에 중단한다.
- 기존 요약의 입력 버전·원본 해시를 유지한다. 구버전 작성물은 보존하고 재확인 필요 이유를 표시한다. 자동 재생성하지 않는다.

## 웹 구성과 데이터 경계

- 기존 결과 탭 옆에 ‘보고서 작성안’을 추가한다.
- 상단: 선택한 C안, 선택 이유, 지금 할 일, 실행 조건·실패 시 행동.
- 상태: 권고 선택 / 실행 준비 / 작성안 생성·검토 상태를 구분.
- SECTION 1~5는 빠른 이동과 접힘 영역으로 읽는다. 요점, 근거 원문 보기, 가정, 미확인 사항, 부록을 분리한다.
- `result_overview.report_plan`은 순수 파생 데이터다. 웹 열기·새로고침·탭 이동은 저장 기록을 변경하지 않는다.
- 기존 `/api/synthesize`를 재사용하되 새 작성안 지원 여부를 확인한다. 원본 토론의 `turns`는 변경하지 않고, 새 모델 결과는 `syntheses`에 별도로 보존한다.

## 검증 범위

STEP↔SECTION 매핑, 후보 하나·유효 ID 검증, 근거 ID 연결, 정정 전/후 이력, 가정·미확인 구분, 구실행 미리보기, 모호한/깨진 응답, 호출 취소·한도·중단, 구버전 서버 차단, 읽기 시 모델 호출 0, 원본·설정 불변을 확인한다. 실제 기존 실행으로 웹을 열어 가독성과 근거 이동을 검증한다. 모의 모델 응답을 실제 총괄 호출 성공으로 보고하지 않는다.

## 라운드 16 검수 반영 · 입력 v4와 서버 운영

`report_writing_plan.md`는 디스크에 저장된 결과 파일 목록과 분리한 파생 문서다. PBL 작성안이 있는 실행에만 조회 대상으로 노출한다. 프로젝트별 OS 파일 잠금으로 포트가 달라도 제어판 서버를 하나만 실행한다. 기본 주소는 `http://127.0.0.1:8765/`이며, 새로 켠 프로세스는 기존 서버의 식별 정보를 확인한 뒤 해당 주소를 안내한다.

총괄 입력 v4는 지지 검토에 대한 부분 수용·조건부 응답도 포함한다. 110,000바이트를 목표로 설명 발췌를 줄이고, 반복되는 객체의 필드명을 표의 열 목록으로 묶는다. 더 큰 입력에서는 단계별 서술·초기 주장 요약·최종 후보와 연결되지 않은 씨앗을 제외하고 범위를 기록한다. 최종 판단·실행 조건·모든 후보·응답 ID와 판정·구조화 손익과 실패 분석을 유지한다. 긴 응답 설명은 발췌 한도와 건수를 명시하며, 연결 대상 불명 응답을 합의 근거로 추정하지 않는다.

목표 안에 들지 않으면 기존 연구 모드의 확장 상한과 같은 130,000바이트까지 허용한다. CLI 전달이 stdin이라는 로컬 코드와 기존 상한에 근거한 내부 예산이며, 특정 모델의 토큰 한도 보증은 아니다. 가장 작은 입력도 상한을 넘으면 모델 호출 전에 중단한다. 모든 길이의 기록을 반드시 넣기 위해 조건·숫자를 없애거나, 자동으로 호출을 여러 번 하는 설계는 채택하지 않는다. 실제 모델 호출 품질 검증은 여전히 별도다.
