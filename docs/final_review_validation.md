# 평가 기준 기반 최종 검토 적용·검증

적용일: 2026-10-21. [설계 조사](professor_review_research.md)에 대한 사용자 승인 후 구현했다.

## 적용한 동작

- 새 연구의 ‘교수 관점 적대적 비판’을 ‘평가 기준 기반 최종 검토’로 바꿨다. 결함이 있다는 전제를 없애고, 근거 있는 지지와 원안 유지 판단을 허용한다. 지적·수정 건수를 채우지 않는다.
- `review_assessment`에 실제 검토 대상 ID, 평가 기준, 유지할 요소의 근거, 범위·한계, 판정 이유를 저장한다. `no_material_defect`는 ‘검토 범위 내 중대한 결함 없음’이라는 모델 판단이다.
- 지적에는 확인된 결함이라는 주장, 미확인 전제, 조건부 위험, 선택적 제안, 지지의 분류와 기준·근거·영향을 기록한다. 미확인을 오류로 올리지 않도록 지시한다.
- 최종 단계에서 지적을 수용·부분 수용·기각하고 수정 또는 유지 이유를 남긴다. 근거 없는 비판을 기각해도 원안을 유지할 수 있다. 선택적 제안 자체는 모델이 중요하다고 표시해도 핵심 미해결 차단 항목으로 세지 않는다.
- 빈 지적 목록만으로 검토 통과를 추정하지 않는다. 대상·기준·이유가 누락되거나, 판정과 지적 목록이 충돌하거나, 선정 후보를 다른 참가자가 최종 검토한 기록이 없으면 권고를 보류한다.
- 요약 화면에 AI별 판정·검토 기준·유지 이유·한계를 표시하고, 토론 화면에 지적 분류와 채택·기각 근거를 표시한다. `professor_review.md`와 기존 JSON 원문 파일명은 유지한다.
- `protocol_version=3`과 기존 단계 ID·순서를 유지하고, 새 실행에만 `review_policy_version=1`을 저장한다. UI·터미널의 새 연구 모두 적용한다. 이전 실행은 조회·재개 시 원래 검토 기준을 유지한다. 오래된 서버에 새 화면만 연결된 경우 새 연구 시작을 차단한다.
- 연구 7절차·합의 6절차 및 기본 호출 수는 늘리지 않았다.

## 검증 범위

실제 AI 토론·연결 테스트·모델 호출은 **0회**다. 테스트의 오류와 비판은 합성 자료이며 실제 AI 오답이나 연구 결과로 사용하지 않는다. 오프라인 검사는 기록 처리와 제어 흐름을 검증한다. 실제 모델의 억지 비판 발생률이 줄었다거나 보고서 성적이 높아졌다는 실험 결과는 아니다.

자동 검사는 비판의 근거가 참인지, 평가 기준 해석과 반례가 성립하는지, 기각 이유가 충분한지까지 확정하지 않는다. 화면의 판정은 모델의 보고로 표시하며, 실제 교수의 심사나 독립 검증 완료로 표현하지 않는다.

현재 제어판: `http://127.0.0.1:8765/`. 시작 버튼을 누르기 전 모델 호출 없이 대기한다. 기존 실행 재개에는 이전 기준이 적용되므로 개선 기준을 사용하려면 새 연구를 시작한다. 커밋과 인증·전역 설정 변경은 수행하지 않았다.
